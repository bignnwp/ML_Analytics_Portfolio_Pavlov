# HR Analytics SQL Project

[English](README.md) | [Русский](README.ru.md)

**Тип проекта:** Data Analytics / SQL Engineering  
**Технологии:** PostgreSQL 14+, чистый SQL (оконные функции, массивы, CTE, представления)

## О проекте

Senior-level SQL-проект на реалистичной HR-базе данных. Цель — показать продакшен-качество запросов для типичных HR-аналитических задач: демография сотрудников, учёт вакансий, загрузка проектов, анализ истории окладов и маппинг грейдов.

В базе: **~90 человек, 85 сотрудников, полная история окладов с несколькими повышениями (включая точные +25%), 22 проекта с командами и руководителями, оргструктура и зарплатные грейды**. Специально заложены краевые случаи (сотрудники старше 65 лет, вакантные позиции, руководители проектов, которые не всегда входят в массив команды).

## Бизнес-вопросы

- Какие сотрудники старше 65 лет?
- Сколько вакантных должностей?
- Сколько уникальных людей задействовано на каждом проекте (включая руководителя)?
- У кого было повышение оклада ровно на 25%?
- Какова средняя сумма договора по годам?
- У кого самый низкий и самый высокий оклад за всю историю?
- Какой текущий оклад у сотрудников и в какие грейды он попадает?
- Как аккуратно отдать переиспользуемую информацию о сотрудниках через представление?

## Что сделано

- Спроектирована чистая нормализованная схема (person → employee → position → structure, история окладов, проекты с массивами + руководитель).
- Наполнена реалистичным объёмом данных с историческими изменениями зарплат.
- Написаны продакшен-стиль запросы с `DISTINCT ON`, `LAG`, `LATERAL`, `UNNEST`, CTE и оконными функциями.
- Создано переиспользуемое представление `employee_info`, которое корректно берёт текущий оклад из истории и учитывает как участников команды, так и руководителей проектов.
- Добавлены дополнительные аналитические запросы для портфолио (траектории зарплат, нагрузка руководителей, распределение по грейдам, стоимость проекта на человека).

## Ключевые технические решения

| Тема | Решение |
|------|---------|
| Текущий оклад | Берётся из последней записи `employee_salary` через `DISTINCT ON`, а не из устаревшего поля `employee.rate` |
| Команды проектов | Учитываются и массив `employees_id`, и `assigned_id` (руководитель) |
| Повышения на 25% | Точное сравнение `salary = prev_salary * 1.25` с помощью `LAG` |
| Вакантные позиции | Классический anti-join (`LEFT JOIN ... WHERE emp_id IS NULL`) |
| Дизайн представления | CTE + set-based агрегация проектов, готово к использованию в продакшене |

## Как запустить

```bash
psql -U postgres -c "CREATE DATABASE hr_analytics;"
psql -U postgres -d hr_analytics -f schema.sql
psql -U postgres -d hr_analytics -f seed.sql
psql -U postgres -d hr_analytics -f views/employee_info.sql
```

Затем выполняйте любой файл из папки `queries/`.
