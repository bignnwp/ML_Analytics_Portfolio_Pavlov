# Production-система прогнозирования оттока клиентов

[English](README.md) | [Русский](README.ru.md)

**Тип проекта:** MLOps / промышленное применение машинного обучения  
**Версия Python:** 3.11–3.12  
**Репозиторий с исходным кодом:** [bignnwp/churn_ml_production](https://github.com/bignnwp/churn_ml_production)

## О проекте

Production-oriented реализация проекта по прогнозированию оттока клиентов банка. Модель выведена за рамки отдельного ноутбука: код организован в виде Python-пакета, обучение отделено от инференса, предсказания доступны через REST API, а проект дополнен автоматическими проверками качества кода и артефактами для развёртывания.

## Цель

Построить сопровождаемый ML-процесс вокруг модели оттока: подготовка данных и feature engineering, обучение и оценка модели, сериализация, инференс через API, автоматизированное тестирование, контейнеризация и конфигурация развёртывания.

## Архитектура и основные компоненты

| Компонент | Реализация |
|---|---|
| ML-пайплайн | Модульный пакет в `src/churn_ml`; подготовка данных, feature engineering, обучение и оценка разделены по модулям |
| Модель | Random Forest; подбор гиперпараметров через `HalvingRandomSearchCV` |
| Сохранение модели | Сериализация с помощью `joblib` |
| API предсказаний | REST-сервис на FastAPI с endpoint `GET /health` и `POST /predict` |
| Схема API и валидация | Pydantic; интерактивная документация OpenAPI / Swagger UI по адресу `/docs` |
| Автоматизированные тесты | Pytest; тесты находятся в `tests/` |
| Контейнеризация | Docker и Docker Compose |
| Манифесты оркестрации | Kubernetes Deployment и Service в папке `k8s/` |
| CI-пайплайн | GitHub Actions: линтинг, форматирование, проверка типов, тесты и сборка Docker-образа |

В процессе обучения рассчитываются Recall, Precision, F1, ROC-AUC и Average Precision. Путь к данным передаётся явно при запуске обучения, а не зашивается в код обучающего модуля. Обученная модель сохраняется в виде артефакта `.joblib`.

## Инструменты разработки и контроль качества кода

Помимо ML- и API-стека, в проекте настроен отдельный набор инструментов Python-разработки:

| Инструмент | Роль в проекте |
|---|---|
| **Poetry** | Управление зависимостями и Python-пакетом; конфигурация хранится в `pyproject.toml`, зафиксированные версии зависимостей — в `poetry.lock` |
| **Ruff** | Линтинг и форматирование Python-кода; используются группы правил `E`, `F`, `I`, `B`, `UP` и `SIM` |
| **mypy** | Статическая проверка типов исходного кода в `src/` |
| **pre-commit** | Автоматический запуск проверок перед созданием commit |
| **pre-commit-hooks** | Проверка пробелов в конце строк, конца файлов, YAML, TOML, JSON и маркеров конфликтов слияния |
| **pytest** | Запуск автоматизированных тестов |

Конфигурация pre-commit также запускает Ruff (включая форматирование) и mypy. Настройки Ruff находятся в `pyproject.toml`, поэтому правила линтинга и форматирования хранятся в системе контроля версий вместе с проектом.

## CI/CD и развёртывание

Workflow GitHub Actions запускается при push и pull request в ветки `main` или `master`. Он подготавливает Python 3.11, устанавливает Poetry и зависимости проекта, после чего выполняет:

1. `ruff check` — линтинг;
2. `ruff format --check` — проверку форматирования;
3. `mypy` — статическую проверку типов;
4. `pytest` — автоматизированные тесты;
5. Сборку Docker-образа — в отдельной job после успешного прохождения проверок качества.

Приложение можно упаковать с помощью Docker или Docker Compose. В репозитории также есть Kubernetes-манифесты Deployment и Service; документация описывает развёртывание в локальных Kubernetes-средах, например Minikube, kind или k3d.

## Документация и артефакты процесса

В исходном репозитории подготовлены:

- **Model Card** — описание назначения модели, данных, признаков, подхода к обучению, метрик оценки и предполагаемого применения;
- **BPMN-диаграммы** — описание жизненного цикла модели: подготовка данных, feature engineering, обучение, оценка, review, deployment, monitoring и retraining;
- **Документация API** — генерируется на основе схемы FastAPI / OpenAPI и доступна через Swagger UI по адресу `/docs` при запущенном сервисе.

- Документирование модели и её жизненного цикла с помощью Model Card и BPMN.
